# 지원서 양식 분석 및 자소서 초안

1. 이슈 본문·후속 답변·대화·첨부 파일(PDF·이미지)에서 지원처(기관·연구실·회사), 직무 또는 프로그램명, 모든 문항 원문과 문항별 글자 수 제한(`limit`)을 추출한다.
   - Actions에서는 `.archive-input/attachments.json`과 같은 폴더의 첨부 원본 파일을 읽어 문항과 글자 수 제한을 추출한다. 지원서 양식 첨부는 공개 아카이브로 복사하지 않으므로 출력의 `attachments`는 빈 배열로 반환한다.
   - 기존 지원 건이 있으면 해당 `content/applications/<slug>/` 폴더를 재사용한다. 독립된 지원서·자소서 요청이고 지원 건이 없으면 지원처·직무를 확인해 `CLAUDE.md`의 지원 스키마대로 `index.md`를 함께 작성한다(공고 분석 자료가 없는 배열 필드는 빈 배열 `[]`).
   - 지원처·직무가 불분명하거나 첨부 파일을 읽을 수 없어 문항을 추출할 수 없으면 작성자에게 되묻는다(Actions에서는 `question` 상태와 빈 배열 반환).
2. 양식에 나온 순서대로 문항마다 `content/applications/<slug>/essay-<n>.md`(`n = 1, 2, ...`)를 작성한다. 같은 지원 건에서 이미 있는 문항은 이전 번호를 유지하고, 새 문항은 사용 중인 번호 다음부터 배정한다.
3. 문항마다 `content/entries/`의 공개 항목(`public: true`, `public` 미기재 포함)만 검토해 적합한 소재 2~3개를 고른다. 적합한 공개 항목이 적으면 실제 후보만 쓴다. `public: false` 항목과 비공개 첨부에서 알게 된 내용은 어떤 필드나 본문에도 쓰지 않는다.
   - 각 항목의 본문, `summary`, `metrics`, `tags`, 기존 `## 자소서 재료`, 이슈 작성자의 답변·편집본에서 확인된 사실만 사용한다.
   - frontmatter의 `materials` 배열에 가장 추천하는 순서대로 `{ entry, reason, draft }`를 채운다.
     - `entry`: 공개 항목 ID(`content/entries/` 기준 `.md`를 뺀 값)
     - `reason`: 이 문항에 해당 항목이 맞는 구체적인 이유(한 문장)
     - `draft`: 해당 소재로 문항에 직접 답하는 한국어 초안. `limit`이 있으면 공백 포함 `limit` 이내로 쓴다.
   - frontmatter의 `entries`에는 `materials`에 사용한 공개 항목 ID를 중복 없이 담는다.
4. 기록에 없는 개인 기여, 구체적 역할, 정량 성과, 선택 이유 등은 절대 지어내지 않는다. 초안을 보강하기 위해 작성자가 직접 확인하거나 채워 넣어야 할 항목은 frontmatter의 `checks` 문자열 배열에 구체적으로 적는다(예: `"팀 프로젝트에서 본인이 직접 맡은 구현 범위 확인"`, `"파이프라인 적용 후 줄어든 작업 시간 등 정량 성과 확인"`).
5. `essay-<n>.md`의 본문은 가장 추천하는 첫 번째 소재(`materials[0]`)의 초안으로 채운다.
   - `limit`이 있으면 frontmatter와 파일 앞뒤 개행을 뺀 **초안 본문**의 글자 수를 공백 포함으로 세어 제한의 **90~100%**가 되도록 다듬고 `materials[0].draft`도 같은 내용으로 맞춘다.
   - 확인된 사실만으로 제한의 90% 이상을 채우기 어렵다면 사실을 지어내지 말고, 작성자에게 동기·본인의 역할이나 결정·확인 가능한 결과·배운 점에서 부족한 사실 3~5개를 질문한다(Actions에서는 `question` 상태).
   - `limit`이 없으면 임의의 글자 수 한도를 만들지 않는다.
   - 공고 분석(`job-analysis`)에서 넘어온 경우 `index.md`와 문항별 `essay-<n>.md`를 하나의 결과로 함께 반환한다.
6. 작성자가 `[다듬기 요청]`으로 문항·선택 소재·편집본을 보내거나 이전 질문에 댓글로 답한 경우, 기존 `essay-<n>.md`의 문항 번호와 나머지 소재를 보존하면서 선택한 소재의 `draft`와 본문을 확인된 사실에 맞춰 다듬는다.
   - 편집본이나 답변에서 새로 확인된 역할·행동·결과·회고는 해당 공개 활동 파일의 `## 자소서 재료` 아래에 **답변 날짜**와 함께 보강한다(섹션이 없으면 생성하고 원문·이전 답변을 보존하며 중복 추가 금지).
   - 답변으로 해결된 항목은 `checks`에서 빼고, 여전히 확인이 필요한 항목만 남긴다.
