# 자소서 초안

1. 이슈 또는 대화에서 지원처·직무·문항 원문과 명시된 글자 수 제한을 확인한다. 기존 지원 건이 있으면 해당 폴더를 재사용한다. 독립된 자소서 요청이고 지원 건이 없으면 회사·직무를 확인하고 `CLAUDE.md`의 지원 스키마에 맞춰 `index.md`를 함께 작성한다. 공고 분석 자료가 없는 배열 필드는 빈 배열로 둔다.
2. 문항에 맞는 공개 경험 2~3개와 각각을 고른 근거를 제안한다. 경험이 적으면 실제 후보만 쓴다. 원문·해당 항목·기존 `## 자소서 재료`·이슈 작성자의 답에서 이미 확인된 내용을 먼저 모은다.
3. 초안에 필요한 사실이 부족하면 동기, 본인의 역할이나 결정, 확인 가능한 결과, 배운 점에서 3~5개 질문을 고른다. 이미 확인된 사실은 다시 묻지 않는다. 예를 들어 “팀이 만든 기능 중 직접 맡은 부분은 무엇이고, 어떤 선택을 했나요?”라고 묻는다. 대화에서는 답을 기다린다. Actions에서는 `question` 상태로 제안할 경험과 질문만 반환한다. 작성자가 답하면 원문·이전 질문과 새 답을 함께 읽고 같은 문항에서 계속한다. 공고 분석에서 넘어온 경우 해당 이슈의 분석 결과도 완성해 함께 반환한다.
4. 확인된 사실로 문항에 직접 답하는 한국어 초안을 쓴다. `content/applications/<slug>/essay-<n>.md`에 `question`, `entries`, 주어진 경우 `limit`를 넣는다. 같은 지원 건에서 같은 문항은 이전 번호를 유지하고, 새 문항은 사용 중인 번호 다음부터 배정한다. `entries`에는 실제 인용한 공개 항목 ID만 넣는다.
5. 제한이 있으면 frontmatter와 파일 끝 개행을 뺀 **초안 본문**의 글자 수를 공백 포함으로 세고, 제한의 90~100%가 될 때까지 다듬는다. 글자 수를 채우려면 새 사실이 필요할 경우 작성자에게 묻는다. 제한이 없으면 임의의 한도를 만들지 않는다.
6. 답변에서 새로 확인된 역할·행동·결과·회고는 각각 해당 활동의 `## 자소서 재료` 아래에 **답변 날짜**와 함께 보강한다. 섹션이 없으면 만들고 원문과 이전 답변을 보존한다. 동일 이슈를 다시 처리할 때 같은 근거와 답변을 중복 추가하지 않는다.
