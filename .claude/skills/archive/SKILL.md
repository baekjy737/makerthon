# 활동 기록

이슈 본문과 이슈 작성자의 후속 답변, 또는 대화에서 제공한 자료를 함께 읽는다. 날짜·개인 역할·성과를 뒷받침하는 문장을 찾는다. GitHub 저장소 링크가 있으면 README를 읽어 프로젝트 설명을 확인한다. 팀 전체의 실적과 학생 개인의 기여를 구별한다. 링크를 열 수 없으면 확인된 메모만 사용한다.

## 지정한 항목에 메모 추가

`memo` 요청에서는 본문에 지정한 경로가 `content/entries/` 안에 실제로 존재하는 항목 Markdown인지 확인한다. 대상이 모호하면 정확한 경로를 묻는다. 기존 frontmatter를 보존하고 해당 파일에 메모로 확인된 내용만 추가한다. 활동 내용은 본문에, 개인의 동기·판단·회고는 `## 자소서 재료`에 보강한다. 같은 답변이 이미 반영됐으면 반복해서 쓰지 않는다.

## 활동 기록 또는 보강

1. 기존 항목의 제목·날짜·주최·저장소 링크를 대조한다. 같은 활동이면 기존 항목에서 새롭게 확인된 부분만 보강한다. 이름만 같은 별도 활동인지 구분할 수 없으면 작성자에게 확인한다.
2. 신규 기록은 활동 날짜와 학생의 역할을 확인한 뒤 작성한다. 연도와 월이 있으면 해당 정밀도로 기록할 수 있다. 날짜나 역할이 빠졌으면, 예를 들어 “언제 진행한 활동인가요? 당시 직접 맡은 일은 무엇인가요?”처럼 빠진 사실만 묻고 답을 기다린다. 댓글 답변을 받으면 원래 메모와 합쳐 같은 절차를 계속한다.
3. `CLAUDE.md`의 항목 스키마로 `content/entries/<slug>.md`를 작성한다. 활동의 종류를 하나 고르고, 한 줄 요약과 본문에 학생이 맡은 일과 확인된 결과를 쓴다. 수상이나 정량 성과는 명시적인 근거가 있을 때만 추가한다.
4. 제공된 이미지·PDF만 해당 항목과 연결한다. 로컬에서는 사용자가 지정한 공개 첨부를 확인해 `public/archive/<slug>/`에 복사한다. Actions에서는 준비된 첨부 목록에서 원본을 확인하고 `CLAUDE.md`에 따라 `{name, entry}`로 복사를 요청한다. 항목의 frontmatter에는 각 대상 파일의 `archive/<slug>/<파일명>`을 한 번씩 적는다. 원본을 읽을 수 없으면 첨부를 다시 요청한다.
