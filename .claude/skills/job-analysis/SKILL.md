# 공고 분석

1. 이슈 또는 대화의 공고 원문·링크와 지원 직무를 확인한다. 링크를 읽을 수 없으면 공고 본문을 요청한다. 같은 회사의 여러 직무 중 어느 직무인지 불분명하면 직무를 묻는다.
2. 공고의 업무·필수 요건·우대 사항을 근거로 요구 역량과 키워드 5~10개를 뽑는다. 공고가 짧으면 확인되는 요건만 쓴다. 공고에 없는 지원 조건이나 마감일을 추가하지 않는다.
3. 모든 활동 항목을 대조한다. 공개할 수 있는 경험부터, 관련 공개 항목을 `matches`에 점수 내림차순으로 넣는다. `score`는 요건을 직접 수행한 근거와 성과의 구체성에 따라 0~100으로 평가한다. `reason` 한 문장에 공고의 요건과 항목의 실제 행동을 연결한다. 공개된 근거가 부족한 요구 역량은 `gaps`에 모은다. 적합한 경험이 없으면 빈 `matches`가 유효하다.
4. 기존 지원 건의 회사·직무·공고를 대조한다. 같은 공고를 다시 처리할 때는 같은 `content/applications/<slug>/index.md`와 원래 `created`를 유지한다. 새 지원 건은 회사와 직무가 드러나는 slug를 만들고 `CLAUDE.md`의 지원 스키마대로 저장한다. 사이트가 이 파일의 `matches`로 맞춤 이력서를 구성한다.
5. 문항이 있으면 원문과 각 글자 수 제한, 해당 지원 건을 가지고 `.claude/skills/essay/SKILL.md`를 이어서 수행한다. Actions에서 답변이 필요하면 `question` 상태로 제안할 공개 경험과 질문만 반환한다. 이때 작성한 분석은 저장되지 않는다. 같은 이슈에서 답변을 받으면 원 공고를 다시 분석해 지원 건·초안·자소서 재료를 하나의 결과로 반환한다.
