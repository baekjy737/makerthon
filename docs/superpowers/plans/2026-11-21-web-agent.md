# 웹에서 AI 요청하기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 학생이 사이트 안의 대화창에서 이슈를 만들고, 첨부를 올리고, AI 질문에 답하고, 반영 결과를 보게 한다. AI 실행은 지금의 Actions 그대로다.

**Architecture:** 브라우저 모듈 `src/lib/agent.ts`가 GitHub REST API(PAT)로 이슈·댓글·업로드 브랜치를 다룬다. `AgentDialog.astro`가 `Base.astro`에 한 번 붙어서, 페이지의 이슈 작성 링크 클릭과 `openIssue()` 호출을 받아 대화창을 연다. `ai-content.mjs prepare`는 `upload/<nonce>` 참조를 추가로 받아들이고, `ai.yml`은 반영 뒤 그 브랜치를 지운다.

**Tech Stack:** Astro(정적), TypeScript, vitest, GitHub REST API(`fetch`), GitHub Actions. 의존성 추가 없음.

**Spec:** `docs/superpowers/specs/2026-11-21-web-agent-design.md`

**담당:** Claude-4. 이 Task에 한해 `.github/workflows/ai.yml`, `.github/scripts/ai-content.mjs`(GPT-1 소유)와 `src/layouts/Base.astro`(Task 2 소유) 수정권을 가진다. 브랜치 `task-22-web-agent`, PR 제목 `[Task 22] 웹에서 AI 요청하기`.

## Global Constraints

- 브라우저에 Anthropic/Claude 키를 두지 않는다. Claude 호출은 `ai.yml`에만 있다.
- 스킬 문서(`.claude/skills/*`), 이슈 템플릿, `ai.yml`의 트리거 조건·route 판정·Claude 단계는 바꾸지 않는다.
- PAT는 `localStorage` 키 `agent-token`에만 저장하고 `https://api.github.com` 요청의 `Authorization: Bearer`로만 쓴다.
- 업로드 참조 줄은 정확히 `첨부: upload/<nonce>/<filename>`, `nonce`=`/^[a-z0-9]{16}$/`, `filename`=`/^[A-Za-z0-9_-][A-Za-z0-9._-]{0,99}$/`.
- 업로드 파일 최대 10MB(10 * 1024 * 1024), 형식은 PNG·JPEG·GIF·WEBP·PDF.
- 진행 확인 간격 10초, `working` 경고 기준 40분.
- 토큰이 없으면 기존 동작(새 탭에 이슈 작성 URL)이 한 번의 클릭으로 가능해야 한다.
- UI 문구는 한국어, 기존 컴포넌트처럼 스타일은 컴포넌트 `<style>` 안에. 작업 전 `.claude/skills/apple-design/SKILL.md`를 읽는다.
- 의존성을 추가하지 않는다. `npm test`와 `npm run build`를 둘 다 통과시킨다.

## Review Focus

- 잘못되었거나 만료된 PAT(401/403/404): 대화창이 "토큰을 확인해 주세요"를 보여주고 토큰을 지울 수 있어야 한다. 조용히 실패하면 안 된다. → 22.1 `githubError` 테스트
- 이슈 생성은 성공했지만 업로드가 실패한 경우: 이슈를 만들기 **전에** 업로드하므로, 업로드가 하나라도 실패하면 이슈를 만들지 않고 오류를 보여준다. → 22.3 수동 확인 항목
- 이름이 한글뿐인 첨부(`이력서.pdf`): `safeFilename`이 빈 이름 대신 `file-1.pdf` 같은 이름을 만든다. → 22.1 테스트
- 같은 이슈에 대한 오래된 질문: 질문 뒤에 작성자가 이미 답했으면 상태는 `working`이다. → 22.1 `issueStatus` 테스트
- 이슈 본문에 다른 저장소나 `../` 섞인 업로드 참조: `prepare`가 무시한다. → 22.2 `uploadRefs` 테스트

### Task 22.1: 브라우저 GitHub 클라이언트 `src/lib/agent.ts`

**Files:**
- Create: `src/lib/agent.ts`
- Test: `tests/agent.test.ts`

**Interfaces:**
- Consumes: `IssueLabel`, `IssueOptions`, `issueUrl` from `src/lib/issue.ts`
- Produces:
  - `TOKEN_KEY = 'agent-token'`, `RECENT_KEY = 'agent-recent'`
  - `type AgentStatus = 'working' | 'question' | 'done' | 'failed'`
  - `interface Comment { author: string; bot: boolean; body: string; createdAt: string }`
  - `parseIssueUrl(href: string, repo: string): IssueOptions | null` — `https://github.com/<repo>/issues/new?labels=…&title=…&body=…`만 받는다. 다른 저장소, 라벨이 `IssueLabel`이 아니면 null.
  - `safeFilename(name: string, index: number): string`
  - `newNonce(): string`
  - `uploadLine(nonce: string, filename: string): string` → `` `첨부: upload/${nonce}/${filename}` ``
  - `issueStatus(comments: Comment[], since: string, now: Date): { status: AgentStatus; slow: boolean }`
  - `class GitHubError extends Error { status: number }`, `githubError(status: number): string` (한국어 안내 문구)
  - `createClient(repo: string, token: string)` → `{ uploadFiles(files: File[]): Promise<string[]>; createIssue(o: IssueOptions): Promise<{ number: number; url: string; createdAt: string }>; comments(n: number): Promise<Comment[]>; reply(n: number, body: string): Promise<void> }`
  - `openIssue(repo: string, o: IssueOptions): void` — 대화창이 있으면 `window.dispatchEvent(new CustomEvent('agent:open', { detail: o }))`, 없으면 `window.open(issueUrl(repo, o), '_blank', 'noopener')`. 대화창은 `document.querySelector('[data-agent-dialog]')`로 확인한다.

const repo = 'me/site';
test('parseIssueUrl: 자기 저장소의 이슈 작성 URL만 읽는다', () => {
  const href = issueUrl(repo, { label: 'archive', title: '[기록] ', body: '### 활동 메모\n\n한글' });
  expect(parseIssueUrl(href, repo)).toEqual({ label: 'archive', title: '[기록] ', body: '### 활동 메모\n\n한글' });
  expect(parseIssueUrl(href.replace('me/site', 'evil/site'), repo)).toBeNull();
  expect(parseIssueUrl(`https://github.com/${repo}/issues/new?labels=bug&title=a&body=b`, repo)).toBeNull();
  expect(parseIssueUrl(`https://github.com/${repo}/issues/3`, repo)).toBeNull();
});
test('safeFilename: 허용 문자만 남기고 비면 file-<n>', () => {
  expect(safeFilename('My CV (final).pdf', 0)).toBe('My-CV-final.pdf');
  expect(safeFilename('이력서.pdf', 1)).toBe('file-2.pdf');
  expect(safeFilename('../.env', 0)).toBe('file-1.env');
  expect(safeFilename('a'.repeat(300) + '.png', 0)).toHaveLength(100);
});
test('newNonce는 16자 소문자·숫자', () => {
  expect(newNonce()).toMatch(/^[a-z0-9]{16}$/);
  expect(newNonce()).not.toBe(newNonce());
});
test('uploadLine 형식', () => {
  expect(uploadLine('abcdefghij012345', 'cv.pdf')).toBe('첨부: upload/abcdefghij012345/cv.pdf');
});
describe('issueStatus', () => {
  const since = '2026-11-21T00:00:00Z';
  const bot = (body: string, t: string) => ({ author: 'github-actions[bot]', bot: true, body, createdAt: t });
  const me = (body: string, t: string) => ({ author: 'me', bot: false, body, createdAt: t });
  const at = (m: number) => new Date(Date.parse(since) + m * 60_000);
  test('댓글 없음 → working, 40분 넘으면 slow', () => {
    expect(issueStatus([], since, at(5))).toEqual({ status: 'working', slow: false });
    expect(issueStatus([], since, at(41))).toEqual({ status: 'working', slow: true });
  });
  test('질문·완료·실패', () => {
    expect(issueStatus([bot('<!-- archive-question -->\n언제였나요?', '2026-11-21T00:03:00Z')], since, at(4)).status).toBe('question');
    expect(issueStatus([bot('PR #12 병합으로 기록을 반영했어요.', '2026-11-21T00:03:00Z')], since, at(4)).status).toBe('done');
    expect(issueStatus([bot('이미 같은 내용이 기록되어 있어요.', '2026-11-21T00:03:00Z')], since, at(4)).status).toBe('done');
    expect(issueStatus([bot('자동 처리에 실패했어요. 실행 로그: x', '2026-11-21T00:03:00Z')], since, at(4)).status).toBe('failed');
  });
  test('질문 뒤 내 답이 있으면 working이고, slow는 내 답 시각부터 센다', () => {
    const c = [bot('<!-- archive-question -->\n?', '2026-11-21T00:03:00Z'), me('2025년 3월', '2026-11-21T00:30:00Z')];
    expect(issueStatus(c, since, at(50))).toEqual({ status: 'working', slow: false });
  });
});
test('githubError: 401·403·404는 토큰 안내', () => {
  for (const s of [401, 403, 404]) expect(githubError(s)).toContain('토큰');
  expect(githubError(422)).not.toContain('토큰');
});

- [ ] **Step 3: 순수 함수 구현** — `issueStatus`는 의미 있는 댓글(봇 댓글 중 표의 문구를 담은 것, 또는 작성자 댓글) 중 마지막 것으로 판정한다. 판정 표는 사양 "진행 상태 판정"을 따른다. `slow`는 `working`일 때만, 기준 시각 = 마지막 작성자 댓글 시각 또는 `since`. `safeFilename`은 확장자를 소문자로 분리하고, 이름의 허용 밖 문자 묶음을 `-`로 바꾼 뒤 앞뒤의 `-`와 `.`를 지우고, 비면 `file-${index + 1}`를 쓰고, 전체 100자로 자른다(확장자 유지).

- [ ] **Step 4: `createClient` 구현** — 모든 요청은 `https://api.github.com/repos/${repo}/…`에 `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `Authorization: Bearer <token>`. `!ok`면 `throw new GitHubError(githubError(status), status)`.
  - `uploadFiles`: 파일 수가 0이면 `[]`. 하나라도 10MB를 넘거나 `type`이 이미지·PDF가 아니면 요청 전에 throw. `GET git/ref/heads/main`으로 sha를 얻고, `POST git/refs`로 `refs/heads/upload/<nonce>`를 만든 뒤, 파일마다 `PUT contents/<filename>`(`branch: 'upload/<nonce>'`, `content`: base64, `message: 'chore: 첨부 업로드'`)을 보낸다. 반환값은 `uploadLine` 배열이다. 이름이 겹치면 `safeFilename` 결과 앞에 `<index>-`를 붙인다.
  - `createIssue`: `POST issues` `{ title, body, labels: [label] }`.
  - `comments`: `GET issues/<n>/comments?per_page=100`. `bot`은 `user.type === 'Bot'`.
  - `reply`: `POST issues/<n>/comments`.

- [ ] **Step 1: 대화창 마크업** — `<dialog data-agent-dialog data-repo={repo}>`(네이티브 `<dialog>`, `showModal()`, Esc로 닫힘, 제목에 `aria-labelledby`). 화면은 네 가지다.
  1. **토큰 없음**: 설명 한 줄, 버튼 "GitHub에서 열기"(기본 버튼, 기존 URL 새 탭) / "토큰 연결하고 여기서 하기". 토큰 입력칸(`type=password`, `autocomplete=off`)과 PAT 만드는 법 링크 `https://github.com/settings/personal-access-tokens/new`, 필요 권한(저장소 하나, Issues·Contents 읽기·쓰기) 안내.
  2. **작성**: 제목 입력, 본문 `textarea`(받은 `IssueOptions`로 채움), 이미지·PDF 파일 선택(`accept="image/png,image/jpeg,image/gif,image/webp,application/pdf"`, multiple), 공개 저장소면 첨부가 처리 중 공개된다는 안내 한 줄, "보내기".
  3. **진행**: 이슈 링크, 댓글을 말풍선으로(작성자 오른쪽, 봇 왼쪽, `<!-- … -->` 주석은 지우고 텍스트로만 렌더 — `innerHTML` 금지), 상태 배지(`working`=작업 중 + 스피너, `question`=답변 입력칸·"답하기", `done`=완료 + PR 링크, `failed`=실패 + 로그 링크). `slow`면 "응답이 늦어요" + `https://github.com/<repo>/actions` 링크.
  4. **오류**: `GitHubError` 문구. 401/403/404면 "토큰 지우기" 버튼을 함께 둔다.
