# 웹에서 AI 요청하기 — 설계

작성일: 2026-11-21 · 결정: 사용자와 리더(Claude-1) 인터뷰 · 구현: Claude-4 (Task 22)

## 목표

학생이 GitHub 이슈 화면으로 넘어가지 않고 **사이트 안에서** 기록·메모·공고·지원서·추천을 요청하고, AI의 되묻기에 답하고, 반영 결과를 확인한다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| AI 실행 | **지금처럼 GitHub Actions(`ai.yml`) + 구독 토큰 시크릿 `CLAUDE_CODE_OAUTH_TOKEN`.** 브라우저에는 AI 키를 두지 않는다. Anthropic API 키(종량제)는 쓰지 않는다. |
| 웹 ↔ Actions 연결 | **이슈를 그대로 쓴다.** 사이트가 GitHub REST API로 이슈를 만들고 댓글을 단다. `ai.yml`의 트리거·route·되묻기 흐름과 스킬 문서, 출력 형식(`files`/`attachments`/`status`)은 바꾸지 않는다. |
| 인증 | 학생이 만든 **fine-grained PAT**(해당 저장소 하나, `Issues: Read and write`, `Contents: Read and write`). 브라우저 `localStorage`에만 저장하고 "토큰 지우기"를 둔다. OAuth 로그인은 콜백 서버가 필요해 제외. |
| 화면 | 사이트의 모든 "이슈 작성" 진입점(`issueUrl`을 쓰는 링크·버튼)을 가로채 **요청 대화창**을 연다. 토큰이 없으면 대화창이 "GitHub에서 열기"(기존 동작)와 "토큰 연결"을 보여준다. |
| 진행 표시 | 10초마다 이슈 댓글을 읽어 `작업 중 → 질문 / 반영됨 / 실패`를 보여준다. 이슈 번호를 저장해 화면을 떠났다 와도 이어 본다. |
| 되묻기 | 질문 댓글(`<!-- archive-question -->`)을 채팅처럼 보여주고, 답하면 API로 댓글을 단다(기존 `issue_comment` 재실행 흐름). |
| 첨부 | 이미지·PDF를 요청마다 새 브랜치 **`upload/<nonce>`** 에 커밋하고 이슈 본문에 참조를 적는다. `ai-content.mjs prepare`가 이 참조만 GitHub API로 내려받는다. 반영이 끝나면 워크플로가 그 브랜치를 지운다. 파일당 10MB. |
| 반영 | 지금처럼 PR → 빌드 통과 시 자동 squash 병합 → 배포. 미리보기·확인 단계는 넣지 않는다. |
| 기존 경로 | 이슈 템플릿과 이슈 작성 URL 경로는 그대로 남긴다(토큰 없는 학생용). |

## 첨부 브랜치를 요청마다 따로 두는 이유

인터뷰에서는 공용 `uploads` 브랜치에 커밋하고 끝나면 폴더를 지우기로 했다. 하지만 파일을 지우는 커밋을 해도 git 기록에는 남아서, 공개 저장소에서는 계속 열람할 수 있다. 요청마다 브랜치를 따로 두고 끝나면 **브랜치째 지우면** 어느 브랜치에서도 닿지 않게 된다. 이슈가 열리기 전에 업로드해야 하므로(`issues: opened`가 바로 실행됨) 이슈 번호 대신 무작위 nonce를 쓴다.

## 이슈 본문의 첨부 참조 형식

```
첨부: upload/<nonce>/<filename>
```

- `nonce`: `[a-z0-9]{16}` (브라우저 `crypto.getRandomValues`)
- `filename`: `[A-Za-z0-9._-]{1,100}`, `.`로 시작하지 않음. 브라우저가 원래 이름을 이 규칙으로 바꾼다.
- 한 줄에 하나. 이 형식이 아닌 줄은 무시한다.

## 진행 상태 판정 (댓글만 보고)

이슈 작성자 = 토큰 주인. 댓글을 시간순으로 볼 때:

| 마지막 의미 있는 댓글 | 상태 |
|---|---|
| 없음, 또는 작성자 댓글 | `working` |
| 본문에 `<!-- archive-question -->` | `question` |
| `PR #` 와 `병합` 포함 | `done` |
| `이미 같은 내용이 기록되어 있어요` | `done` |
| `자동 처리에 실패` 또는 `반영하지 않았어요` | `failed` |

`working`이 40분 넘게 이어지면 "응답이 늦어요"와 Actions 실행 목록 링크를 보여준다(`ai.yml` 제한 35분).

## 보안·개인정보

- PAT는 이 사이트 출처의 `localStorage`에만 둔다. 다른 곳으로 보내지 않고, `api.github.com` 요청에만 쓴다.
- `prepare`는 `upload/` 참조를 **자기 저장소(`GH_REPO`)·형식 검증을 통과한 경로**에서만, 워크플로의 `GITHUB_TOKEN`으로 받는다. 크기 제한과 매직바이트 검사(`extension`)는 기존과 같다.
- 공개 저장소에서 업로드 브랜치는 처리되는 동안 공개다. 이는 지금의 `user-attachments` 첨부도 링크로 열람할 수 있는 것과 같은 수준이며, 대화창에서 안내한다.
- 실패·질문으로 끝난 요청의 업로드 브랜치는 재실행을 위해 남는다(알려진 한계).
